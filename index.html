    THE LAB / LOOK UNDER THE BUTTON

    One click, three jobs.

    1 · Find the device

    An IP address identifies a network destination. A port identifies a service. DHCP can change a device address; manual entry makes that visible. This version does not scan or discover devices.

    2 · Say what you want

    GET asks for information; POST requests an action. The path identifies what to do. A response confirms receipt, not necessarily the result you intended. Watch the message panel as you press a button.

    3 · Respect the boundary

    Browsers enforce cross-origin and secure-context rules. A website cannot casually control a plain-HTTP local device. Python is the local bridge. Use the page it serves for real control; opening index.html by itself provides the demo.

    Pairing, tokens, and LG/Samsung

    The helper's key protects access to the helper; it is not device pairing. Other TV families may negotiate a pairing prompt and client token using WebSockets. A WebSocket maintains a two-way connection rather than one independent HTTP request per button.

    LG webOS and Samsung adapters are not implemented in this Roku-first version. Their protocols and permissions need checking against the particular TV. Compatibility varies by model, firmware, and settings; this is not a universal remote.

    A tiny automation experiment

    In demo mode, press Home, Down, Right, OK. A sequence becomes a program. A real TV may respond at different speeds or show another menu. Start with deliberate individual presses instead of blindly replaying a macro.

    When the button doesn't land.

    • No helper: Python 3 must already be installed. Keep its window open and use the printed URL.
    • Phone can't open it: use phone mode and the PC's LAN address on the same trusted network. Guest isolation, a VPN, or a firewall can block it. Do not expose it to the Internet or disable your firewall.
    • No Roku response: verify its IP and power. Inspect Settings → System → Advanced system settings → Control by mobile apps → Network access. Firmware may require Enabled; decide whether to permit network control on your trusted LAN. Developer mode is not needed for these basic commands.
    • Some keys fail: support for TV volume/power varies. A successful response does not prove the TV changed.

    Phone mode uses unencrypted HTTP on your local LAN. Anyone with the helper key and network access can control the selected device. Use a trusted private network and stop the helper when finished. No permission changes, package installations, cloud requests, or persistent device records.
